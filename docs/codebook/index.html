What I changed, and why it is shaped that way

Thirteen commits across two features: admins promotable by a click, and people able to ask their own way into a league. The code that matters, with the reasoning that produced it.

range 015c2b9 → f7144ed, my commits only · backend +1080/−77 · frontend +2216/−249 · infra nothing — no workflow, manifest, Dockerfile or nginx change · verified 887 backend · 270 frontend · 86 e2e · gates 0

ScopeWhat is mine, and what rode along

Thirteen commits. Other sessions pushed into the same window — docstring corrections, test hygiene, a build-context fix — and those are not covered here. Nothing in this change touches infrastructure: no CI workflow, no Kubernetes manifest, no Dockerfile, no nginx config. The only thing that reaches the cluster is a new table, created by the boot migration.

The two features

  • OSAP — an admin promotes a linked member by pressing his name, instead of typing an address.
  • OSJR — a person asks his own way into a league, and an admin rules on it. Ends up as: the admin sends a link.

Backend · 1The data model

backend/app/data/models.py 
class JoinRequest(Base):
    __tablename__ = "join_requests"

    group_id: Mapped[int] = mapped_column(ForeignKey("groups.id"), primary_key=True)
    user_id:  Mapped[int] = mapped_column(ForeignKey("users.id"),  primary_key=True)

    user: Mapped[User] = relationship()

Why a second table and not a column, or a reuse of link_requests.

The existing claim table is keyed (player_id, user_id), both non-null — it says "I am that man on your sheet" and needs him standing there. A newcomer has no man to name, which is the whole reason this exists. It cannot share that key.

A column on players was worse still: an unapproved request sitting on the row the ballot reads is one careless query away from behaving like a link. Same reasoning the claim table was built on.

The composite primary key is the "one live request per league" rule, enforced by the database rather than by code — unlike a claim, there is nothing else in the key to make a second row look different.

No hand-written migration. Base.metadata.create_all in migrate_schema creates it, which is additive and idempotent — the repo's convention. Verified on production after promotion: table present, both foreign keys, composite PK, 0 rows.

Backend · 2The seam that stops an orphan player

backend/app/data/roster.py 
def refuse_unlinkable(session, user, *, other_than=None) -> None:
    """Whether this account may be attached to a man here, said once."""
    if not user.email_verified:
        raise HTTPException(409, "този акаунт още не е потвърден")
    taken = _linked_to(session, user.id, other_than=other_than)
    if taken is not None:
        raise HTTPException(409, f"този акаунт вече е свързан с {taken.name}")

This is an extraction, not new logic. Both checks already lived inside link_user, which runs them at the moment it writes.

That ordering is fine for every existing door — they all have a player already. It is wrong for a join approval, which creates the player it is about to link. Discovering afterwards that the account was never eligible leaves a man on the team sheet who exists only because a refusal arrived one line too late.

So the question is asked before anything is created. link_user now calls the same function, so there is one copy of the rule and not two.

Backend · 3The approval

backend/app/data/joins.py — 140 lines, the whole aggregate 
def approve_join(session, user_id: int) -> Player:
    request = get_or_404(session, JoinRequest,
                         {"group_id": group_of(session), "user_id": user_id},
                         "join request")
    refuse_unlinkable(session, request.user)          # before anything exists
    player = add_player(session, request.user.name)   # the only name we have
    linked = link_user(session, player, request.user) # every rule, re-read
    session.delete(request)
    session.commit()
    return linked

It routes through link_user rather than writing player.user_id itself. A request can sit in the queue for a week, and in that week the account can lose its verification or be linked to somebody else. Going through the shared door means every refusal it makes still applies at the moment the admin acts, not only at the moment the person asked.

It takes no player_id. It used to — a picker let the admin say which man on the roster the asker was. That was a real guard while the join request was the only way in. It stopped being one when both doors landed on the league page: a man who is on the sheet names himself there and arrives as a roster claim with his own name on the row. The picker was asking the admin a question the asker had already answered, with a blank field and no way to know what belonged in it. Removed, along with the body model and the endpoint parameter.

Backend · 4The API surface

POST /api/{slug}/joinAsk to be let in. RequireUser. Refuses 409 if he already plays here or already asked.
DELETE /api/{slug}/joinTake it back. Keyed on the caller, so it can only ever be his own.
GET /api/{slug}/admin/joinsThe queue. Admin-gated, group-scoped.
POST /api/{slug}/admin/joins/{user_id}Approve. No body.
DELETE /api/{slug}/admin/joins/{user_id}Reject. 404 if somebody else already ruled.
GET /api/{slug}/admin/pending{joins, claims} — one read for the badge.
GET /api/{slug}/meGained join_pending, beside the claim_player_id it is the sibling of.
GET /api/admin/usersWidened: this league's admins plus its own linked players (OSAP).
GET /api/leaguesAdded, shipped, then removed with the directory.

The member-facing routes sit on the league router, not under /admin. The person doing it is not an admin — he is a stranger to this league who wants not to be, and the row he writes grants him nothing until one of them says so. Same placement as the existing claim endpoints.

Frontend · 1Two doors on one card

frontend/src/components/JoinLeague.tsx — 141 lines 
if (!me?.authenticated) // → "Присъедини се", to /auth?next=<this league>
if (me.is_admin || me.player_id !== null) return null;
if (claimed !== null)   // → "waiting to be linked to <name>", withdraw

The claim door existed and could not be found. Saying "I am that man" has worked since OSPC, but only from inside a match page's vote widget, after picking yourself out of the "Кой си ти?" list. Somebody looking at the league itself had no way to reach it — so the only door he could find was "let me in as a newcomer", and an admin was left guessing which man he was. The person knows. The app was asking the wrong one.

The signed-out branch returns a card, not null. It used to return nothing, so a visitor who arrived from a shared link landed on a page with no way in and no explanation.

Frontend · 2A count that cannot lie

frontend/src/lib/pendingWork.ts 
let version = 0;
const listeners = new Set<() => void>();

export function workChanged(): void {
  version += 1;
  for (const listen of listeners) listen();
}

export function usePendingCount(isAdmin, slug): number {
  const version = usePendingWorkVersion();
  const { data } = useResource(
    () => (isAdmin && slug ? api.pendingWork() : Promise.resolve(null)),
    [isAdmin, slug, version],
  );
  return data ? data.joins + data.claims : 0;
}

Why a store and not a prop. The badge is in the header; the queues are on a page under it. Neither is the other's parent, and threading a callback from the Shell through the router to a queue component is a prop nobody else needs.

A version counter, not the count. The server owns the number; caching it here would give two places that can disagree about how much work is waiting. This only says "it changed, go and ask again".

It exists because the first cut lied. Fetched once, the badge went on claiming work an admin had just finished — the same lie as having no badge, told the other way round. Caught by a browser test, not by review.

Frontend · 3The header break I caused

Adding the count beside the Админ badge pushed the account menu off the screen. At 375px the avatar rendered at x=370..404 in a 375-wide window: past the right edge, untappable. Every signed-in journey starts at that control.

The suite's existing 375px check could not see it. The header clips rather than grows, so document.documentElement.scrollWidth still read 375 — green, and broken.

Three changes, the last a trade:

  • The count moved onto the avatar's corner — position:absolute, out of the row's width budget entirely, and what a notification actually looks like.
  • The league name caps at 72px instead of 90; the nav gap tightened.
  • The "Админ" badge is hidden below sm. It was asserted at phone width by a test written after flex once squeezed it to a green dot. Two guarantees wanted the same 65px. I inverted that assertion rather than deleting it, with the reasoning in place: the badge is a label whose meaning is one tap away in the menu; the menu is not substitutable.

The suite now measures the account menu against the viewport, since the check it had could not catch this class of break.

Frontend · 4The link, and what it replaced

frontend/src/components/ShareLeague.tsx 
const link = `${window.location.origin}/${slug}`;

One line, and it is the whole mechanism. The link is the league's own address: nothing is minted, nothing expires, a forwarded one keeps working, and the same one serves next season. Contrast the existing GroupInvite, which mints a token per person and dies when spent — right for "become this specific player", wrong for "here is the group".

It replaced a public directory. I built /leagues with search, shipped it to production, and then removed it: the link answers "which group?" more directly, and the directory cost a publicly enumerable list of every group on the platform for no benefit. Removed entirely rather than left as a second way in — page, route, endpoint, model, reserved slug, both entry points, asset, six tests, and the router-parse floor that tracked the count.

Removing it left a live URL claiming an outage. /leagues fell through to /:slug, asked the API for a league called "leagues", and the Shell reads a failed identity call as "Няма връзка със сървъра". Redirected to /groups.

That is also what any mistyped league address does today — "server unreachable" rather than "no such league". Pre-existing, not fixed here, and worth its own increment.

TestsWhere each claim lives, and what was witnessed

  • Rules at API tier — test_join_requests.py (13) and test_admin_candidates.py (4): who is refused, what an approval writes, what a rejection leaves behind.
  • Isolation — test_tenant_isolation.py: another league's requests are neither listed nor counted. Its module docstring declared /api/admin/users deliberately unswept; my change falsified that, so the note was rewritten rather than left contradicting the file.
  • Component tier — states only, because jsdom does not open a Mantine dropdown. Both suites say so where it matters.
  • Browser tier — four journeys, kept to what only a real engine can show: the picker, the account menu, phone width, and that the assets load.
  • Not duplicated — 401/403 on /api/admin/users were already asserted in test_api.py; cited rather than rewritten.

ReviewWhat I would flag

  • Two queues, two near-identical components in PlayersPage. They differ now — the join row has no player and the claim row has two labelled halves — but they were a copy at one point and would merge cleanly if they converge again.
  • The badge keeps state outside React. Justified above, but it is global mutable state and counts as such.
  • Wrong door still makes a duplicate. Somebody on the roster who presses "Искам да вляза" gets a second row. Recoverable — delete the spare, link the account from the editor — and the card puts naming yourself first to make it rare.
  • The roster picker lists already-linked players. The server refuses, but the refusal tells the asker that player has an account. Pre-existing on the match page.
  • "Админ" is gone on phones. A real loss, taken deliberately.
  • frontend/tsconfig.tsbuildinfo is a tracked build artifact, committed by another session. I kept it out of every commit rather than churn it; it wants a git rm --cached and a gitignore line.
