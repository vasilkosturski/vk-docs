Design

Seam: PlayerEditor takes a RosterPlayer and an email | null and reports changes upward — it owns no reads, so the page stays the only thing that knows how the two lists are fetched. A fourth property on a man is a field in one component, not another row mode. bio stayed off PlayerRecord deliberately: that type is what the standings engine sees.
